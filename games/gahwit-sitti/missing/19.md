# 19 · Notifications

**Ring 2 · Size S–M · Spec:** `COMPLETE_SPEC.md` 3, 4

## Where it stands

- No notifications.
- The Mobile Notifications package (`com.unity.mobile.notifications`) isn't installed.
- The save has one `settings.notifications` switch (schema v2).

## What's missing

**Setup**
- Install the Mobile Notifications package for iOS and Android.
- On Android 13 and later, ask for the notification permission at run time.

**When to ask**
- Ask only after the first memory, never at first launch.

**Limits**
- At most 2 a day.
- None between 23:00 and 08:00 local time, unless the player chose the Ramadan night option. That option isn't in the settings design yet.
- These numbers belong in `balance.json` (02).

**The six types**

| Trigger | Kind |
|---|---|
| Energy full | Local |
| A regular is due | Local (08) |
| A chapter task is affordable | Local |
| A friend needs help with hosting | Server push (ring 3, 20) |
| An event ends in 6 hours | Local (18) |
| Away for 3 days | Local |

**Text**
- The spec writes them in Amman dialect, but `/CLAUDE.md` asks for neutral Arabic in system text (02). Decide, then put the text in the UI string table.

**Settings**
- One switch per type (`COMPLETE_SPEC.md` 4). The save has only one switch, so this needs a schema change and a migration with a test.

**How to build it**
- A plain C# `NotificationPlan` class takes the game state and the time, and returns the notifications to schedule. It respects the daily cap and the quiet hours. Test it.
- Reschedule when the app goes to the background, and clear on open.

**Push for hosting** (ring 3)
- Firebase Cloud Messaging on the phone.
- An Apple push key and a sending service on the platform. Keep the key in a secret store.

## Done when

- "Energy full" arrives at the right time, respecting the quiet hours and the daily cap.
- Each type can be turned off on its own.
- Nothing is asked or sent before the first memory.
