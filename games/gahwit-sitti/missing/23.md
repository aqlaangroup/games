# 23 · Build, test and release pipeline

**Ring 1 · Size M · Backlog 23, 24 · Spec:** `BUILD_GUIDE.md` 9, 10; `PLAN.md` 1, 2, 5; `/CLAUDE.md` (performance, Git)

## Where it stands

- **iOS:** `_Game/Editor/BuildTools.cs` writes an Xcode project to `unity/Builds/iOS`.
  - An Xcode build started at 01:33 on 2026-10-31.
  - The `.app` holds only an empty `Frameworks` folder, so there's no finished phone build yet.
- **Android:** never built, and no signing key is set up.
- **Tests:** no CI. The 49 EditMode tests only run inside the Editor.
- **Quality:** the game never sets a quality level, and the graphics setting isn't connected.
- **Version:** 0.1.0, with build numbers 0 (iOS) and 1 (Android).
- **Performance:** never measured on a phone.
- **Git LFS:** the rules in `unity/.gitattributes` only cover `unity/`. Images, video or audio saved in `art/` or elsewhere outside `unity/` would go into plain Git.

## What's missing

**Builds**
- **Finish an iOS phone build.** `_Game/Editor/IosPostBuild.cs` adds the Sign in with Apple capability.
- **An Android build:**
  - an app bundle (`.aab`), signed with a key kept in a secret store, never in the repo
  - targeting the API level Google Play currently requires
- **Uploads:** TestFlight, and Google Play's internal testing track (backlog 24).
- **A build number** that goes up on every build, automatically.

**Continuous integration**
- Run the EditMode tests on every push. Options: GameCI with a Unity licence, or a self-hosted Mac runner.
- Run `dotnet test` for the platform.
- Make iOS and Android builds every night, or on demand.

**Phones and performance** (`PLAN.md` 1, 5; backlog 23)
- **Two test phones:** a 3 GB Android (a Galaxy A14-class phone) and an iPhone XR. A build on both every week.
- **Profile against the targets:** 60 fps on mid-range phones, 30+ on the weakest, and no allocations in `Update`.
- **Places that allocate on every tap** (not every frame, but they add up). Pool these:
  - `OrdersView.Refresh` destroys and rebuilds every order card on each change.
  - `CafeScreen.BuildStyleChips` rebuilds the style chips on each refresh.
  - `BoardView.Refresh` runs a LINQ query (`Game.IsWanted`) for all 63 squares on each change.
- **Quality levels:** auto, low and high. Auto chooses by the phone's memory and GPU, and lowers shadows and effects.
- **A memory budget** for the 3 GB phone.

**Download size** (`PLAN.md` 1)
- Keep the first download under 150 MB.
- Later chapters and events download in the background through Addressables. Addressables only builds local content today. It still needs:
  - a remote load path and a CDN
  - a way to update the content catalogue
- Check the app's size on every build.

**Git**
- Add LFS rules for `art/`, and any other folder outside `unity/` that will hold images, video or audio.
- Commit after each working feature, with tests passing (`/CLAUDE.md`).

**Before every store build** (`BUILD_GUIDE.md` 9)
- 30 minutes of play with no crash.
- Purchases tested in the stores' sandboxes.
- Offline mode works.
- Arabic text checked on every new screen.
- Crash reporting on (16).

## Done when

- A tester installs from TestFlight and from Google Play's internal track.
- CI runs every test on each push.
- The 3 GB Android holds 30+ fps in the café, and the first download is under 150 MB.
