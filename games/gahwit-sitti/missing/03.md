# 03 · Platform server

**Ring 1 (deploy, rewards) · Ring 2 (purchases, config, events) · Size M–L · Spec:** `/platform/README.md`; `COMPLETE_SPEC.md` 9, 10, 11, 14, 16; `/CLAUDE.md` (platform rules)

Updated on 2026-10-31 after commits `a4e9ac9` and `e487de7` ("player accounts, cloud save, support and staff admin on PostgreSQL").

## Where it stands

**Built and tested** (33 tests in `platform/tests/Platform.Tests`; this review didn't run them)
- **Storage and setup:**
  - EF Core on PostgreSQL, with migrations.
  - Games register from `games/*/game.json` at startup.
  - The signing key comes from configuration.
- **Player accounts:**
  - guest accounts, sign-in with Apple and Google, linking
  - access and refresh tokens, sign-out
  - birth year, language and account deletion, with a purge job
- **Cloud save:** versions, conflicts, a size limit, and sanity flags on impossible jumps.
- **Other player routes:**
  - support tickets
  - server time (now with `nowMs`)
  - rate limits on sign-in routes
- **Purchases:** `/purchases/verify` now takes the player from the access token.
- **Staff API:**
  - sign-in and roles (owner, producer, support, viewer)
  - player search and detail
  - grants and support tickets
  - staff management and an audit log

**Still stubs or placeholders**
- **Receipt checks** refuse every receipt (`NotConfiguredVerifier`).
- **The Apple and Google webhooks** do nothing.
- **Apple token revocation** on account deletion only logs. It needs the Sign in with Apple key (`.p8`).
- **Google sign-in client ids** in `game.json` are `[set after Google Cloud setup]`.
- **Not deployed.** `baseUrl` in `unity/Assets/Content/Resources/Config/platform.json` is a placeholder.

## What's missing

**Deploy (ring 1, so testers get cloud save)**
- Choose hosting, such as a container and a managed PostgreSQL.
- HTTPS only, with logs and database backups.
- Keep `ConnectionStrings:Platform` and `Auth:SigningKey` in a secret store.
- Set `baseUrl` in `platform.json`.

**Gems the game earns (design this first)**
- The game never grants gems (`_Game/Merge/Game.cs`, `_Game/Core/Wallet.cs`). There's still no player route for:
  - level-up gems (`formulas.levelUpGems`) and chapter gems (`chapters[].reward.gems`)
  - the daily login and daily tasks (18)
- **One way to do it:** `POST …/players/me/rewards` with an id such as `levelUp:7` or `chapter:2`.
  - Each id grants once.
  - The server checks it against the latest save and `balance.json`.
- **Spending gems** on energy refills, bubbles, storage slots, premium decor and memory retry skips also needs routes.
- **The wallet at launch.** Check the game gets it at sign-in, so `Wallet.ApplyPlatformBalance` can show it.

**Purchases (ring 2, see 17)**
- Apple: the App Store Server API, and App Store Server Notifications v2.
- Google: the Play Developer API, real-time notifications, and acknowledging every purchase within 3 days.
- Refund rules, including what happens when the gems are already spent.

**Config and events (ring 2, see 18)**
- `GET /config` and `GET /events` exist, but nothing publishes a config or schedules an event. Add staff routes for both (22).
- A minimum game version in the config reply, for the "update required" screen (04).

**Later rings**
- Push sending for hosting (APNs and FCM keys in a secret store) (19).
- Friends, gifts, visits, hosting and the Sitti wall, with moderation (20).
- Ad network revenue import for the dashboards (22).

## Done when

- The platform runs on a public HTTPS address, and a TestFlight build signs in and saves to it.
- A level-up grants its gems once, even when the call is repeated.
- A sandbox purchase on each store is verified and granted once.
